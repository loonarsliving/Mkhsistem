# MK Connect Android — Build Guide

The Android app is a [Capacitor](https://capacitorjs.com) native shell around the
production Next.js web app (`capacitor.config.ts` → `server.url:
"https://mkh.haluoleo.id"`). The WebView always loads the live production
site, so there is no separate frontend to build or deploy for the app itself
— authentication, RLS, Realtime, Storage, and every business rule live in
the one place they always have. The native project only adds app chrome
(icon, splash, permissions) and bridges (`lib/native/*.ts`) that the web
pages opt into when running inside the app.

## Prerequisites

- **Android Studio** (Hedgehog or newer) with Android SDK Platform 34+ and
  a JDK 21 (Android Studio bundles one — no separate install needed).
- Node.js 22+ and the repo's own `npm install` already run once.

## Opening the project

```bash
npx cap sync android   # re-copies capacitor.config.ts + any plugin changes into android/
npx cap open android   # launches Android Studio pointed at the android/ project
```

Or open `android/` directly as an existing project in Android Studio.

## Building locally

```bash
cd android
./gradlew assembleDebug      # → app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease    # → app/build/outputs/apk/release/app-release.apk (or -unsigned.apk, see below)
```

The debug build is signed with Android's standard, non-secret debug
keystore (auto-generated by Gradle) — fine for internal testing, but the
OS will refuse to install a debug-signed update over a release-signed one
or vice versa, so pick one lane per device.

## Release signing

`android/app/build.gradle` reads the release signing config from
environment variables — nothing is hardcoded, and no keystore is ever
committed to this repo:

| Variable | Meaning |
|---|---|
| `MKC_RELEASE_KEYSTORE_PATH` | Path to the `.keystore`/`.jks` file |
| `MKC_RELEASE_KEYSTORE_PASSWORD` | Keystore password |
| `MKC_RELEASE_KEY_ALIAS` | Key alias inside the keystore |
| `MKC_RELEASE_KEY_PASSWORD` | Password for that specific key |

If `MKC_RELEASE_KEYSTORE_PATH` is unset, `assembleRelease` still succeeds
and produces a real, installable **unsigned** release APK — useful for
verifying the release build itself works, but it cannot be installed as an
*update* to a previously-signed install, and should not be distributed as
the final artifact.

### Generating a real release keystore (do this once)

```bash
keytool -genkeypair -v \
  -keystore mkconnect-release.keystore \
  -alias mkconnect \
  -keyalg RSA -keysize 2048 -validity 10000
```

You'll be prompted for a keystore password, a key password, and identity
details (organization: PT Maha Karya Haluoleo). **Store this file and both
passwords somewhere durable and access-controlled (a password manager, not
Slack/email) — losing it means every future release must ship as a new,
separate app** (Android ties updates to the signing key permanently).

### Wiring it into CI (GitHub Actions)

`.github/workflows/android-build.yml` builds both APKs automatically on
every push that touches `android/**` and uploads them as workflow
artifacts. To make the release build actually signed, add these as
**repository secrets** (Settings → Secrets and variables → Actions):

- `ANDROID_RELEASE_KEYSTORE_BASE64` — `base64 -i mkconnect-release.keystore | pbcopy` (or `base64 -w0` on Linux), paste the output
- `ANDROID_RELEASE_KEYSTORE_PASSWORD`
- `ANDROID_RELEASE_KEY_ALIAS`
- `ANDROID_RELEASE_KEY_PASSWORD`

Once set, every CI run produces a properly signed `app-release.apk`
artifact. Locally, `export` the four `MKC_RELEASE_*` variables before
running `./gradlew assembleRelease`.

## Firebase push notifications ("Firebase ready")

The app registers for push and stores the device token
(`supabase/migrations/0021_device_push_tokens.sql`,
`lib/native/push.ts`) — that receiving side is fully wired. Actually
**sending** a push (when a memo/announcement/registration notification is
created) needs a real Firebase project, which nobody has provisioned yet:

1. Create a Firebase project, add an Android app with package name
   `id.haluoleo.mkconnect`.
2. Download `google-services.json` and place it at `android/app/google-services.json`.
3. Add the Google Services Gradle plugin (`com.google.gms.google-services`)
   to `android/build.gradle` and `android/app/build.gradle` — Capacitor's
   push-notifications plugin docs cover the exact snippet.
4. Write a Supabase Edge Function (or scheduled job) that reads
   `mkc_device_push_tokens` and calls the FCM HTTP v1 API whenever a row is
   inserted into `mkc_notifications` — this is genuinely new backend work,
   not something that can be wired without that Firebase project existing
   first.

## App Links (deep links) verification

`AndroidManifest.xml` declares an `autoVerify="true"` intent filter for
`https://mkh.haluoleo.id`. For Android to actually trust it (and open links
in the app instead of the browser), serve this at
`https://mkh.haluoleo.id/.well-known/assetlinks.json`:

```json
[{
  "relation": ["delegate_permission/common.handle_all_urls"],
  "target": {
    "namespace": "android_app",
    "package_name": "id.haluoleo.mkconnect",
    "sha256_cert_fingerprints": ["<SHA-256 of your release signing certificate>"]
  }
}]
```

Get the fingerprint with `keytool -list -v -keystore mkconnect-release.keystore -alias mkconnect`.

## Regenerating app icon / splash assets

`scripts/generate-android-assets.py` (Pillow) regenerates every
mipmap/adaptive-icon/splash PNG from the same "MK" monogram used by the
web app's `app/icon.tsx`. Re-run it if the brand mark changes:

```bash
pip install Pillow
python3 scripts/generate-android-assets.py
```
